## 第 2 轮：实现检测头解剖

### 用户 Prompt（原文）

> 请你帮我引入 检测头解剖 这个功能或模块,，应该对应你说的检测解码链路。因为目前的项目对于检测头是如何将特征图转换成锚点和分类这一块没有解释清楚，我希望引入这个模块，增加对于模型目标检测的理解。前端具体样式你根据情况制作，要求美观且和之前的风格一致。

### AI 修改建议与过程

AI 的方案不是另写一套“演示用”解码，而是先重构共享数据层：

1. 从 `src/model/detect.js` 拆出 `decodeCandidates` 与 `nmsTrace`，让主界面和检测头解剖共用同一份 `output0` 解码；
2. 新增 `headAnatomy.js`，把 2100 个格点映射回 `P3 40×40 + P4 20×20 + P5 10×10`；
3. 新增 `AnchorGrid.jsx`，分层绘制热力图、网格、候选框和 NMS 状态；
4. 新增四步浮层：分支解剖 → 锚点网格 → 置信度筛选 → NMS 抑制；
5. 用无头 Edge 断言“格点中心与解出框的关系”，验证三尺度拼接顺序和行优先展平。

过程中补丁工具因 PowerShell 5.1 参数转义吞掉引号，AI 定位到根因后改用精确的进程参数调用，并重新校验中文编码。这说明 AI 生成的代码仍经过工具链和浏览器验证，而不是直接粘贴。

### AI 最终回复（原文节选）

> **新增：检测头解剖**
>
> - 整屏浮层，四个步骤从左到右讲完「特征图 → 锚点 → 分类分数 → 阈值 → NMS → 框」，底部漏斗实时显示 `3 张特征图 → 2100 个锚点 × 84 个数 → N 个候选 → M 个框`。
> - `① 特征图 → 分支`：颈部三路输入（`m16` P3 / `m19` P4 / `m22` P5）的真实特征图缩略图 + 分支构成（框回归 64 = 4 方向 × 16 DFL bin，类别 80 通道）。
> - `② 锚点网格`：2100 个格点按 stride 铺回图像，每格正好是 `stride × stride` 像素。可在「最高类分数 / 指定类概率」间切换着色。
> - `③ 置信度筛选`：候选框全部叠在图上（示例图 18 个），直观看到「一个目标周围多个格点同时响应」。
> - `④ NMS 抑制`：单步 / 自动播放回放，绿色 = 保留、蓝色 = 当前判定、红色虚线 = 被压掉。
>
> 验证：`npm run probe:head` 四步切换、点格点、NMS 单步与自动播放、两个入口都跑通，无控制台报错；格点映射不变量 12/12 通过。

## 一次“文档纠错”闭环

AI 初稿写了“格点中心偏差在一个 stride 之内”。继续验证后，它认为这句话不够严谨，改成可自动断言的不变量：

```text
|cx − 格点中心| ≤ 半个框宽
```

该断言同时覆盖 P3→P4→P5 的拼接顺序与尺度内行优先展平。README 与探针脚本同步修改，而不是只改界面文案。
